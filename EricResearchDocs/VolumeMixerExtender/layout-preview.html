这一版的关键取舍

  • 两个下拉框置顶Body 第一顺位
    系统页原本把「输出设备」做成单选列表（占 4~5 行），换成下拉框后同样的信息只占 1 行 —— 省下的高度全给应用列表。
  • 端点音量独占一层本次补上
    三层结构：选默认设备（两个下拉框）→ 每个设备各一条音量（端点音量）→ 逐应用音量（合成器）。
    位置按你定的：插在「默认输入设备」与「音量合成器」之间。
    不是按通道做两条（输出/输入各一条），而是枚举每个端点各一条 —— 每台设备都能单独调音量和静音。 图标区分方向（喇叭 = 渲染端点、麦克风 = 采集端点），列表顺序是渲染端点在前、采集端点在后（不加分组标签）。
    行结构/app 行完全一致（图标 + 名称 + 静音 + 音量条），所以名称过长仍走"最多折两行"那条规则。
  • ⚠️ 只列 ACTIVE 端点，且必须过滤掉 V
    按 EnumAudioEndpoints(DEVICE_STATE_ACTIVE) 枚举 ——「已禁用」「未插入」的设备不该出现在这里 （Windows 自己的列表也只列 ACTIVE）。
    ⚠️ 再加一条本项目特有的：把虚拟设备 V 过滤掉（与两个下拉框同一条硬约束）。 而且 V 的音量本来就硬锁 100%、调不动（方案 §5.2），列出来只会是个拖不动的死滑块。
  • ⚠️ 录制模式下这一层仍然可用、而且正好补了方案的缺口
    能调的是监听设备 R 的音量 —— 方案 §5.4 说"录制时请到系统里调 R 的滑块"， 现在这个入口就长在我们页面上，不用切到系统去了。
    V 不在列表里，所以不存在"误调 V"的问题。
  • 输入设备收成一个折叠组默认收起
    渲染端点逐条展开（喇叭图标）；采集端点收成一行「输入设备（N）」 + 展开箭头， 默认不展开；点一下展开、再点收起，子行缩进 28px 表示从属。
    ⇒ 真正的收益是把高度封顶：输入侧不再随设备数增长，页面高度只随渲染端点数量增长。
    ⚠️ 但它没有变矮当前这一屏 —— 本图输入侧有 2 台，收起后占 1 行（44px），比全展开省 44px； 若只有 1 台输入设备，收起前后高度是一样的。
  • ⚠️ 内容区仍然超出一屏实测代价
    收起态（默认）：内容需要 603px，可用 306px ⇒ 超出 297px（约 6.75 行）。
    展开输入设备：需要 691px ⇒ 超出 385px。
    ⚠️ 渲染端点那一侧仍然不封顶 —— 本图只画了 3 台，真实机器上"扬声器 + 耳机 + HDMI + USB" 到 5~6 台很常见 ⇒ 再加 2~3 行（88~132px）。
    共用滚动区意味着打开时基本只看得到"两个下拉框 + 端点音量"，应用列表要滚很远。
    ✅ 已定：接受现状，不压缩 —— 共用滚动区本来就是设计的一部分，滚一下是预期操作不是缺陷。 行高保持 44px（与 app 行等高）。四个旋钮① 行用 40px；② seclabel 折进行内； ③ 这一层限高 + 内部滚；④ 渲染端点也折叠 —— 全部不做。
  • 滑块不走 IPC，TAP 内直调 WASAPI已定
    Slider.ValueChanged 拖动时每秒触发几十次 —— 走管道会打满管道、跟手感变差。 ⇒ 滑块流量一律不走 IPC，pipe 继续只承载"点击/命令"。
    代价（都是必须实现的，不是可选优化）：
    ① WASAPI 封装两边共链（TAP + App 共用一份，⛔ 绝不写两份 —— 枚举顺序/V 过滤迟早不一致）；
    ② 外部改动要回写 UI（键盘音量键改同一台设备时滑块得跟着动）⇒ RegisterControlChangeNotify，回调不在 UI 线程 ⇒ 必须 Dispatcher.RunAsync；
    ③ 得区分"拖动中"与"拖动结束"，拖动中忽略外部回写否则会和手指打架 —— WinUI Slider 没有 IsDragging，要用 Thumb.DragStarted/DragCompleted。
  • 应用列表一行装完
    图标 / 名称 / 静音 / 音量条横排在同一行。侧栏只有 358px 宽，双行排版（名称一行、音量条一行）会把可视应用数从 5 个压到 3 个。
  • 行高从 44 起，按需长高宽度不变
    行宽恒定 330px，绝不横向加宽。高度只在这两种情况下长：① 名称过长（最多折两行，见 Microsoft Teams (工作或学校)）；② 该应用有重定向，名称下补一行端点（见 Google Chrome → 耳机 (2- USB Audio)）。两者同时发生时，名称仍只占两行、端点那行不折。
  • 端点行不折、超长省略
    端点行是单行 + 省略号，全名放 title（悬停可见）。这样"有重定向"的行永远不会比"名称两行"的行更高，高度上限可算得出来：两行名称 ≈ 33px + 端点 ≈ 14px，整行封顶 ≈ 52px。
  • 底栏项是「文字链接」，不是按钮像素实测
    从 docs/verified-after-injection/02-footer-screenshot.png 逐像素取样：模型按钮 94x40 的整框内，除字形外全是纯背景色 —— 无边框、无填充。文字核心 #5a535b、背景 #e8d4e8，正好是 60.6% 前景叠底（TextFillColorSecondary）， 且 R−B 差 = 0 ⇒ 中性灰，不是强调蓝。
    所以底栏改成一排纯文字：静止无框无底，只有一个 40px 高的悬停热区； padding 0 11px + font-size 12（模型按钮 94 = 72 文字 + 11 + 11， 「更多音量设置」6 个汉字正好 72px ⇒ 1 字 = 12px）。
  • 底栏两态（同一个 Footer，靠可见性区分）系统保留区
    系统页：我们只在右侧加一个按钮，别的一概不碰（本图不画系统页）；
    自定义页：[清除重定向] … [设置] … [SystemMixer] —— 左与中只在自定义页出现。
    四项共用同一套样式：不给自己人加颜色或边框 —— 注入实测就是"复制模型按钮的 Style 与 Foreground"， 外面完全看不出哪个是系统的、哪个是我们的。
  • 底栏是「一个」元素实现注意
    `Footer` 是系统页 PageWindow 的子元素，不随内容区一起被换掉。所以三个元素只在首次注入，之后靠 可见性（左、中）与文字（右）在切换的那一刻更新 —— 不是"两套底栏"。

录制模式（本次新增控件）

  • 位置：「默认输出设备」标题行右对齐，同一行。
  • 勾选后的语义翻转已定稿（对应 VirtualAudio-Record-Mirror-Plan.md）：
    勾选：系统默认输出 → V（OC Virtual Speaker，硬锁 100%）； 切之前的那台默认设备 → 监听设备 R；本行标题 →「监听输出设备」。
    取消勾选：完全反向 —— 系统默认输出切回 R，本行标题 →「默认输出设备」。
    ⇒ 两边对称、无中间态。R 不是用户另外选的，它就是从"切之前那台"来的。
  • V 永不显示硬约束
    V 不出现在本页任何列表或标签里，只能由这个复选框间接控制。
    ⇒ 枚举 render 端点时必须过滤掉自己的虚拟端点。否则用户能把它直接选成默认设备， 绕过录制模式、让录制链在"没有监听目标"的情况下空转。
  • 录制模式不持久化已定稿
    勾选状态不跨系统重启保存，每次启动一律从"未勾选"开始。⇒ D 也不用落盘，只活在本次会话内存里。
  • 残留由驱动侧「常开开关」结构性解决已定稿
    V 的插头就是个常开开关：驱动加载后默认未插入，只有我们显式闭合（录制模式打开时 IOCTL）才插入； 模式关 / 程序退出 / 崩溃被杀 → 驱动在 IRP_MJ_CLEANUP 上兜底回未插入。
    ⇒ 「程序没运行」是驱动的上电默认值，不需要任何代码维护 —— 崩溃、被杀、断电、重启全都一样。
    ⇒ 所以宿主侧不需要"待清理标记 + 上次默认设备"落盘与启动对账；D 只活在会话内存里。
  • 当前状态可见：勾选后下拉框的选中值可能不变（R 常常就是原来那台扬声器）。 所以只靠下拉框文字看不出模式已开 —— 复选框本身是唯一的状态指示。若你觉得不够，可以在标题行再加一个状态词（不推荐，会挤）。
  • 实现注意：WinUI 的 CheckBox 默认 MinHeight=32、方框 20px， 会把这行 16px 的标题撑高到 32 —— 需要紧凑模板（MinHeight=0 + 16px 方框）。 已验：CheckBox 可激活、IsChecked 可往返、MinHeight(0) 可设、可挂树 （T18，见 verified-after-injection/11-checkbox-capability.md）。

设置页（本次新增）

  • 入口与返回
    入口 = 自定义页底栏中位的「设置」。返回 = 设置页底栏 中位的「返回」（你定的）。
    ⚠️ 但标题行那个系统后退键仍然在 —— 它是 PageWindow 的元素，点它就是 L2Frame 往回导航 ⇒ 退回 L1，跟底栏的「返回」不是一回事。
    ✅ 已定：保持系统默认行为，不拦 —— 两个返回键行为不同是接受的取舍， ⛔ 不要再为此挂 L2Frame.Navigating（也就不必验 NavigatingCancelEventArgs.Cancel 可写性了）。
  • 底栏三态：三个格子是"复用"的，不是"切换可见性"实现注意
    系统页   [ — ]      … [ — ]    … [ MixerExtender ]
    自定义页 [ 清除重定向 ] … [ 设置 ] … [ SystemMixer ]
    设置页   [ GitHub ]     … [ 返回 ] … [ （占位） ]
    ⇒ 三个格子每页给不同文案 + 不同动作，所以实现必须是"每格一个 handler，进来先读当前页再分发"。
    ⚠️ 不能"每到一页就新挂一个 Click" —— 事件处理器会累积，切两次就会触发两次。
    ⚠️ 这与之前"靠可见性区分"的设想要分开：可见性只用来处理"系统页时左、中必须消失"（因为那几个格子 是我们塞进系统行的，系统页不该有我们的东西），文案/动作则一律靠 dispatch。
  • 左侧 GitHub 只放短标签，不放完整地址实测约束
    按底栏的排版实测算：github.com/EricZhang233/VolumeMixerExtender（43 字符） 在 font-size:12 下约 258px 文字 + 22px 内边距 = 280px； 而底栏可用宽度只有 358 − 8 = 350px，减去「返回」(46) 和右侧占位，装不下。
    ⇒ 所以图上用 「GitHub」，完整地址放 title（悬停可见）。
    ✅ 保持中性灰（已定，不破例）—— 因为底栏各项是"复制系统按钮的 Foreground"得来的，加蓝就破了统一。它看起来不像链接是刻意的：底栏三格是"三种动作"，不是"三个链接"。
  • 打开 GitHub 用 action=open已定
    调 ShellExecuteW(nullptr, L"open", url, nullptr, nullptr, SW_SHOWNORMAL)， 不复用 exec：exec 走 CreateProcessW，只认 exe； "用默认浏览器打开 URL"是 shell 的职责。
    ⚠️ ShellExecuteW 的返回值不是 BOOL —— > 32 才算成功。
  • 右侧「（占位）」
    图上用半透明画出来，只是为了标明这一格已被预留。⚠️ 真实产品里这一格是空的，不画任何东西。
  • 「显示驱动名」本次新增
    控制设备名要不要带括号里的驱动名后缀：扬声器 (Realtek(R) Audio) ↔ 扬声器（默认开）。
    作用面是三处：① 两个下拉框的值；② 端点音量每一行；③ 应用行里"重定向目标端点"那行小字。 三者都来自 PKEY_Device_FriendlyName，必须同步改，不能只改一处。
  • ⚠️ 它只能作用于设备名，绝不能碰应用名线框稿踩到的 bug
    第一版按"去掉结尾括号"全局扫 .nm，结果把 Microsoft Teams (工作或学校) 削成了 Microsoft Teams —— 那是应用名的一部分，不是驱动名，削了就是另一个应用了。
    ⇒ 规则：按"这个元素是不是设备名"来判定（要知道它属于哪个区块）， 不要按"文本正则以 ( 结尾"来判定。 XAML 侧不存在"全局扫"的问题（每个 TextBlock 都是我们自己建的）， 但取值必须取对 Key：设备名走 PKEY_Device_FriendlyName（或 DeviceDesc + InterfaceFriendlyName 自己拼），应用名走会话/进程信息。
  • ⚠️ 它不省高度实测
    开关前后内容高度 603px → 603px（不变）。行高由 min-height:44 钉死，名字短了行还是 44px。
    它省的是折行/截断：显示器音频 (NVIDIA High Definition Audio) 要折两行， 关掉后 显示器音频 一行就够。所以这是可读性设置，不是省空间设置 —— 别指望它缓解上面那条"超出 297px"。
  • 「开机启动」= Run 键 + ToggleSwitch新类型 · 已定
    ⚠️ ToggleSwitch 不在已验列表里（T14 的 10 个类型、T18 的 CheckBox 都不含它）。 同在 Windows.UI.Xaml.Controls 下，预计可用，但按惯例要补一次探针。
    ✅ 开关背后是 HKCU\...\CurrentVersion\Run 的 VolumeMixerExtender 值：
    "<InstallRoot>\vmex.exe" --tray（⚠️ 路径带引号，整条是一根命令行字符串）；
    登录时由 explorer 拉起（⛔ 不是启动时 —— 要注入的 ShellHost 是每会话进程）；
    天然是当前用户未提权的令牌（注入要求同完整性级别）。
    开关语义：初值 = Run 值存在 && 未被系统标记为禁用； 关 = 删 Run 值 + 删禁用标记（⛔ 只删 Run 值会留下 StartupApproved\Run 灰项， 下次打开又被判成"被禁用"）。
    ℹ️ 同日从"计划任务"改过来：一个值就是全部语义，没有 ExecutionTimeLimit / 电池那几项默认值陷阱，也不存在把运行身份写成提权的可能。⚠️ 但控制台子系统仍会在登录时 闪一下黑窗（换 Run 键免不掉）—— 已决定接受，不做子系统改造。
  • 「从系统卸载」置底危险操作
    用 SystemFillColorCriticalBrush 着色（深色主题 #FF99A4）， 靠一个 flex:1 的空白块把它推到内容区底部 —— 它不属于底栏，仍在内容区里（会随内容滚动）。
    连击确认：单击后文案变 再单击{N}次从系统卸载，相邻两次间隔须 ≤ 0.5s， 超时立刻复位；连击 5 次才真卸。
    选连击而不是 ContentDialog：浮层会盖住面板、还得先验 XamlRoot。
    ⭐ 语义 = "退出接管、回落原生行为"，不是"删掉这个软件"： 不删程序文件、不卸驱动、不删配置，只做两件事 —— ① 删除开机自启项 ② 重启 shell（ShellHost 换进程 ⇒ TAP 连同注入一起消失 ⇒ 原生 UI 回来）。
    ⛔ 这两步必须由 App 执行，不能由 TAP 执行：TAP 就活在 ShellHost 里，重启 shell = 它当场自杀； 而且只有 App 能在杀 ShellHost 之前先把 Watcher 停掉，否则 TAP 会被立刻重新注入回来。
    ⇒ 走 action=pipe 通知 App；pipe 不可用就拒绝执行（绝不降级成"TAP 自己重启 shell"）。
    ℹ️ 顺手把「程序文件还在 ⇒ 手动运行一次 exe 即可重新接管」这条也带出来： 所以 App 启动时要写 enabled=1，覆盖卸载时留下的 0。
  • 这页就是"零散小设置项"的收容所
    目前只有「开机启动」「显示驱动名」两项，下面留空 —— 不占位造假的条目。后续小设置项都往「常规」下面加。

已定稿

  • 下拉框的标签带「默认」
    写「默认输出设备」/「默认输入设备」—— 直接说清这个下拉框改的是系统默认设备，不靠额外标记。
  • 应用列表不分组
    平铺一条列表，不按端点分组。
  • 下拉框与列表共用一个滚动区
    整块内容一起滚 —— 实现最简单，也不需要在窄侧栏里做嵌套滚动。
系统页不在本图范围内，我们也不绘制：我们对它的全部改动就是底栏右侧多一个按钮。
系统页本身由系统自己绘制 —— 我们只在它构建好之后把内容区 ListContent.Content 换出、保存引用， 切回时把同一个对象放回去。所以产物里没有、也不需要"系统页"这部分代码。
上面这块内容对应的正是 ListContent 的区域；标题行与底栏是系统的，我们不改。
