## 1. 目标（含"录制电平"这一核心诉求）

- 录制时手工把默认播放设备切到 V → 录屏软件采到 V 的 **无音效、恒满幅** 干净数字流；
- **录屏文件电平恒定满幅**：调小监听音量 / 调小系统音量，录制文件都不会跟着变小（避免"以 50% 录制→分享回放更小声"）；
- 监听程序把 V 的声音镜像到指定真实设备 R → Eric 照常听到；
- **音量只属于 R**，虚拟层彻底不参与。


## 4. 驱动侧设计（V）

### 4.1 端点

| 端点 | 名称 | 类型 | 说明 |
|---|---|---|---|
| Render | `OC Virtual Speaker` | 播放 | 唯一端点；录制期间手工设为默认输出 |

### 4.2 约束

1. **不安装任何 APO / 音效**，端点「音频增强」默认关闭。
2. **只开 Shared 模式**（不暴露独占模式）。
3. 除必要采样率转换外，不做任何处理。
4. **音量硬锁 100%，且不衰减**（见 §5）。

### 4.3 插头 = 常开开关（★ 端点可见性由我们独占控制）

**只注册设备，不默认注册"已插入"的端口。** 插头状态是一个**常开开关**：

| 时刻 | 插头 | 系统里的表现 |
|---|---|---|
| 驱动加载后（默认态） | **未插入** | 端点是 `DEVICE_STATE_UNPLUGGED` ⇒ Win11 设置/快速设置里**根本不出现**，任何进程也选不到 |
| 我们的程序在**录制模式打开**时发 IOCTL | **已插入** | 端点变 `DEVICE_STATE_ACTIVE` ⇒ 可当默认；程序随即把它设为默认 |
| 录制模式关闭 / 程序退出 / 崩溃 / 被杀 | **未插入** | 端点消失；Windows 自动把默认滚回真实设备 |

**机制**（WDK `10.0.26100.0` 实测存在的定义）：

| 用到的定义 | 位置 | 说明 |
|---|---|---|
| `KSJACK_DESCRIPTION.IsConnected` (`BOOL`) | `ksmedia.h:8274` | 报告插头是否插入 |
| `JACKDESC2_PRESENCE_DETECT_CAPABILITY = 0x1` | `ksmedia.h:8277` | 在 `KSJACK_DESCRIPTION2.JackCapabilities` 里声明支持插头检测 |
| `KSEVENT_PINCAPS_JACKINFOCHANGE` | `ks.h:1375` | 告诉系统"插头信息变了，重新查询"，避免等轮询 |
| `KSJACK_DESCRIPTION3.ConfigId` | `ksmedia.h:8289` | 改这个值会**让 audioendpointbuilder 刷新缓存**（注释原文） |
| `DEVICE_STATE_UNPLUGGED = 0x8` | `mmdeviceapi.h:152` | 最终落在 MMDevice 层的状态 |

**为什么必须是"常开"（默认未插入）**：

- 「程序没运行」这个状态因此**不需要任何代码去维护** —— 它就是驱动的上电默认值，
  崩溃、被杀、断电、重启全都一样，**结构性保证**。
- 反过来若默认"已插入"、由程序去关，那么程序崩溃时就必然留下一个可见可选的 V（残留）。
- 驱动必须把"闭合"绑定到调用方的**文件句柄**上：句柄关闭时在 `IRP_MJ_CLEANUP` 里回到未插入，
  **不能只靠程序主动发一条"拔掉"IOCTL**（那样崩溃就又漏了）。

**收益**：宿主程序侧**不需要**"待清理标记 + 上次默认设备"落盘与启动对账这套机制（见 `docs/design.md` §7.9.1）。
✅ **已定：那套对账机制不上** —— 本节的插拔就是替代方案，`pendingRestore` / `previousDefaultId` / 启动对账**全部删除**。

⚠️ 注意：`UNPLUGGED` 端点**不能渲染**、**不能当默认** —— 所以"隐藏"与"能当默认"天然互斥，
插拔只能二选一。"V 只在录制时**存在**"能做到，"V 存在但谁也看不见"做不到。

⭐ **这条也是"从系统卸载"不需要卸驱动的原因**（`docs/design.md` §7.9.2 / 交付文档 §5.7.8）：
卸载只做 **删除开机自启项 + 重启 shell**，**不删程序文件、不卸驱动** ——
因为宿主一退出就没人闭合插头 ⇒ **V 结构性不可用** ⇒ 系统自动回落原生行为，
而且**不需要重启系统**（卸驱动才需要）。驱动留在盘上但完全惰性。
✅ **已定（2026-10-03）**：**没有端点时 Windows 不会显示它** ⇒ 卸载后不会留下"看得见的残留"，
**不必**为此加"卸驱动"这一步。

**待验证**：见 §11 的验收 7–10。

## 5. 音量模型（核心）

### 5.1 原则

- **V 的音量 = 一个常量 100%**：系统读它得到 100%，也改不动它；
- **V 不把任何音量衰减施加到输出上** → 送往 loopback 的数据恒为满幅 0 dB；
- **音量只属于 R**：调 R 的音量、静音 R，与录制链完全无关。

### 5.2 实现（驱动侧，让"锁死"成为结构保证）

- 驱动暴露一个**音量节点，但范围固定为 0 dB（min = max = 0 dB）**：
  - 系统因此显示 100% 且**无法拖动**；
  - 引擎把音量委托给该节点、**不再叠加软件音量**；
  - 驱动**不做衰减** → 数据恒满幅。
- 这样"录制电平恒定"不依赖任何运行时同步，是**结构上锁死的**。

### 5.3 效果

- 录屏文件电平 = 原始满幅，**与你监听的音量、R 的音量、系统音量全部无关**；
- R 的音量/静音只改变你听到的响度，不改变录制。

### 5.4 副作用（已知并接受）

录制时默认设备是 V，键盘音量键 / OSD 会打到 V —— 因为 V 锁死，**按键不会改变任何东西**。
→ 监听音量请到 **Windows 声音设置 / 音量合成器里调 R 的滑块**（R 一直在）。

**不做音量路由**：不实现任何 "V 音量 → R" 的转发，也不做音量键代理。音量与 V 无任何交互。

## 7. 监听程序（V → R）

### 7.1 功能（最小集）

- **采集**：V 的 Render 端点 WASAPI loopback。
- **输出**：渲染到宿主告诉它的真实设备 R。
- **R 的唯一来源 = 宿主**（§8）：`R := 勾选瞬间的默认设备 D`。⛔ **监听程序不自带设置页、不自己枚举设备**
  —— 早先计划的"设置页仅一项：选择监听设备 R"**已取消**（2026-10-03），它与 §8 重复。
- **不处理音量**（§5）。

### 7.2 工程要点

- **格式协商**：V 与 R 的 mix format 可能不同。⛔ **不要手写转换链** —— 见 §7.3 的
  `AUDCLNT_STREAMFLAGS_AUTOCONVERTPCM` + `SRC_DEFAULT_QUALITY`，让 audio engine 做转换。
- **时钟漂移**：V/R **双时钟**，长时间运行累积溢出/欠载 → 自适应补偿（丢/插样本，或按
  `IAudioClock::GetPosition` 微调喂入速率）。⚠️ **格式转换与时钟漂移是两件事**，前者能外包给 WASAPI，后者不能。
- **缓冲/延迟**：默认 10–30 ms。
- **设备枚举**：**监听程序不做**（它只吃宿主给的 R）。R 掉线时**由宿主侧处理** ——
  自定义页那行下拉框就是 R 的选择器，设备消失走同一套列表刷新。⛔ **不做自动重连**（R 回来后重开流即可）。

### 7.3 技术栈（🅿️ 留到驱动层阶段再定）

> 🅿️ **本节的"决定"是在错误的时间点做的**（2026-10-03）：监听程序属于**驱动层阶段**（见文首排期），
> 现在只是把它当作**迁移时的技术备注**留档。**开工时再正式定**。
> 当前**工作假设**：全 C++ / Core Audio —— 因为仓库的 C# 轨道**已删除**，
> 且 C++ 轨道的主要卖点就是"**没有 .NET 运行时、没有第三方库、没有 VC++ Redistributable**"。
> ⛔ 但**不要**把这条当成已锁定的决策去引用。

**工程约定**：与仓库其余部分一致 —— C++20、`/MT` 静态 CRT、x64、Unicode、⛔ 不引第三方库。
链接 `ole32.lib` / `uuid.lib` 即可，都在 SDK 里。

**要用到的 Core Audio 接口**

| 环节 | 接口 / 标志 |
|---|---|
| 采集 V（render 端点的 loopback） | `IAudioClient::Initialize` + **`AUDCLNT_STREAMFLAGS_LOOPBACK`**，`IAudioCaptureClient::GetBuffer/ReleaseBuffer` |
| 渲染到 R | `IAudioClient`（R 端点）+ `IAudioRenderClient::GetBuffer/ReleaseBuffer` |
| 格式协商 | 先读 V 的 `GetMixFormat()`；对 R 调 `IsFormatSupported` |
| COM 公寓 | `CoInitializeEx(COINIT_MULTITHREADED)` —— 全程 MTA，⛔ 不建 STA（没有 UI） |

⭐ **一个能省掉手写重采样器的做法**：渲染侧开
**`AUDCLNT_STREAMFLAGS_AUTOCONVERTPCM` + `AUDCLNT_STREAMFLAGS_SRC_DEFAULT_QUALITY`**（共享模式合法），
就能**把 V 的格式原样喂给 R**，让 audio engine 自己做采样率/位深转换与重采样。
⇒ 常规情况下**不需要自己写格式转换链**（这就是 NAudio `WasapiOut` 帮我们做掉的那部分）。

⚠️ **但漂移仍然要自己处理**：V 与 R 是**两个独立时钟**，长时间运行必然累积溢出/欠载。
`AUTOCONVERTPCM` 解决的是"格式不同"，不是"时钟不同"。
⇒ 仍需自适应补偿（丢/插样本，或按 `IAudioClock::GetPosition` 微调喂入速率）—— 见 §7.2。

## 8. 默认设备切换（**自动化** · 2026-10-03 修订）

> **原决策是"手动切换、无脚本、无看门狗"，本节已推翻。** 现在由 VolumeMixerExtender 接管。

- **宿主**：VolumeMixerExtender 的自定义页（见 `docs/design.md` §7.9.1）。
- **控制件**：**「默认输出设备」标签行右端的「录制模式」复选框** —— 唯一的控制入口。
- **切换规则**（自动、双向对称）：

```text
勾选：  记住当前默认 D → 系统默认切到 V → R := D      标题 → 监听输出设备
取消：  系统默认切回 R（= 记住的 D）                   标题 → 默认输出设备
```

- **R 不是用户另外选的**，它就是从"切之前那台默认设备 D"来的。
- **V 在 VolumeMixerExtender 内永不显示** —— 枚举 render 端点时把它过滤掉，只由复选框间接控制。
- **录制模式不持久化**（2026-10-03 定）：**勾选状态**不跨系统重启保存，每次启动一律从"未勾选"开始。
  ⇒ **D 也只需活在会话内存里**（用于"取消勾选时立刻切回"，不必等 Windows 自己滚）。
- **残留由驱动侧的「常开开关」结构性解决**（§4.3）：V 的插头默认未插入，只有录制模式打开时才闭合；
  模式关 / 程序消失 → 驱动兜底回未插入 ⇒ V 从系统里消失 ⇒ 默认由 Windows 自动滚回真实设备。
  ⇒ **宿主侧不需要"待清理标记 + 上次默认设备"落盘，也不需要启动时对账。**

| 时刻 | 系统默认输出 | V 的插头 | 本页标题 / 复选框 |
|---|---|---|---|
| 平时（未录） | = 下拉框选的那台 | 未插入 | 「默认输出设备」/ ☐ |
| 勾选录制模式 | **V**（我们立刻切过去） | **已插入** | 「监听输出设备」/ ☑ |
| 取消 / 程序消失 | 切回 **R = D** | **未插入** | 「默认输出设备」/ ☐ |

✅ **已定（2026-10-03）：R 只有这一个来源** —— 勾选瞬间的默认设备 D（复选框自动得出）。
早先 §7.1 里"监听程序自己的设置页手选 R"那项**已取消**（重复，且监听程序现在**无 UI**）。
ℹ️ 想换 R 仍然可以：录制模式勾着时，自定义页本行的下拉框**就是 R 的选择器**（标题已变「监听输出设备」）。

## 9. 录屏软件

- **无需特殊配置**：V 是默认播放设备时，任何采集「默认播放设备」的录屏软件都会自动 loopback V。
- **录屏软件自身的音量/增益保持默认（0 dB / 100%）**，不要在软件里再压低 —— 那属于"录制层"的音量，会直接进文件。

## 10. 边界与风险

| 项 | 说明 | 处置 |
|---|---|---|
| **DRM 保护音频** | loopback 对受保护内容返回静音 | 说明，非本方案可解 |
| **独占模式 App** | 绕过共享混音，采不到 | V 只开放 Shared |
| **时钟漂移** | V/R 双时钟 | 自适应重采样 |
| **监听延迟** | V→R 增加 2 个缓冲 | 小缓冲 |
| **采样率不一致** | V 与 R 不同 | 监听程序重采样 |
| **音量键无效** | V 锁死后默认设备上的音量键不变任何东西 | 到系统里调 R（已知并接受） |
| **录屏软件内压音量** | 软件侧音量会进文件 | 保持 0 dB（§9） |
| **忘记切回** | 原为手动切换 ⇒ 忘了就采不到音 | **已由 §8 的自动切换覆盖**，无需外部看门狗。剩余风险见下一行 |
| **状态残留** | 复选框还勾着、宿主进程却没了 ⇒ 系统默认停在 V，而 R 无从恢复 | ✅ **结构性解决**（§4.3）：插头是**常开**的 —— 驱动默认未插入，崩溃/被杀时驱动在 `IRP_MJ_CLEANUP` 回到未插入 ⇒ V 从系统里消失 ⇒ Windows 自动把默认滚回真实设备。**不依赖任何"清理对账"代码** |

## 11. 验收测试

1. **录制恒幅（核心）**：拖动 R 的主音量 / 静音 → 录制电平**不变**。
2. **V 不可调**：尝试调 V 的音量 → **调不动**（系统显示 100%），录制电平不变。
3. **内容一致**：播放测试音（1 kHz 正弦 + 扫频）→ 录制与源频谱一致、电平 = 源满幅。
4. **音效隔离**：开/关 R 音效 → 录制频响**不变**。
5. **端点出现**：**录制模式打开后**，系统声音设置出现 `OC Virtual Speaker`，可作默认设备。
6. **长稳**：连续录制 ≥30 min，无爆音、无漂移断续。

**插头常开开关（§4.3）—— 待验**

7. **默认不可见**：驱动装好、宿主程序未运行 ⇒ `IMMDeviceEnumerator::EnumAudioEndpoints(DEVICE_STATE_ALL)`
   里能查到该端点，但状态是 `DEVICE_STATE_UNPLUGGED`；**Win11 设置 / 快速设置的设备列表里没有它**。
8. **免重启翻转**：程序发 IOCTL 闭合 / 断开 → 端点在 `ACTIVE ↔ UNPLUGGED` 之间切换，
   **无需重启、无需重装驱动**；记录延迟（决定复选框手感）。
9. **消失即回滚**：V 是默认设备时让它变成 `UNPLUGGED` ⇒ Windows 是否自动把默认滚到真实设备？滚到哪台？是不是 D？
10. **重现不抢默认**：V 从 `UNPLUGGED` 变 `ACTIVE` 时，Windows 会不会**自动把默认抢回 V**？
    若会 —— 确认"只在录制模式打开时才闭合"能覆盖掉这个副作用。
11. **崩溃兜底**：录制模式开着时 `taskkill /F` 杀宿主 ⇒ 驱动是否在 `IRP_MJ_CLEANUP` 里回到未插入、
    默认是否自动滚回真实设备（**这是"常开开关"最关键的验收项**）。
12. ~~**卸载后不残留**~~ ⇒ ✅ **已定，无需验收**（2026-10-03 Eric）：**没有端点时 Windows 不会显示它**。
    宿主退出 ⇒ 没人闭合插头 ⇒ V 是 `UNPLUGGED` ⇒ 系统设置里也不会出现。
    ⇒ "卸载不卸驱动"这条成立，不必为此改成"卸驱动"（那会要求重启系统，与"重启 shell 即回落"冲突）。
